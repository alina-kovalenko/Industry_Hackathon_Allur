# Проверка связки frontend, backend и ML — 8 октября 2026

Проверена текущая ветка `main`, исходный коммит `a0b4b19d9d88b6ffab1caf3465fe7b9b3b336f8a`. Работа выполнена по исходникам из GitHub, а не по старой локальной копии.

## Откуда берутся числа на экране

| Экран / действие | Источник | Роль ML |
|---|---|---|
| Данные сервера: участки, KPI, инциденты | `/api/session`, тестовые записи кейса | KPI рассчитаны формулами |
| Инциденты и прогноз | `observed_dashboard.prediction` из `/api/session` | Настоящий вызов `predict_risk`, веса из `models/downtime_risk.json` |
| Остановка участка | `/api/scenarios/run` → `calculate_stop_scenario` | Детерминированный расчёт потока, не прогноз ML |
| История, воспроизведение, сброс | Серверный `LineSession` | Прогноз заново вычисляется по выбранному наблюдаемому срезу |
| Factory overview, Line analytics, Scenario lab | Симулятор 12 условных станций в браузере | Локальные правила риска; не результат обученной модели |

Отдельную симуляцию нельзя выдавать за цифровой двойник реальных 12 станций: в документах кейса есть только три участка и нет измеренных очередей, временных рядов датчиков и паспортных циклов. На серверном экране очередь остаётся `null` / «Нет данных».

## Исправления

- Серверный экран теперь показывает числовые оценки ML по всем трём участкам, дату наблюдений, целевое событие и ограничения. Раньше выводилась только общая текстовая метка.
- Метки источника отличают серверные данные от браузерной симуляции; ссылка на главную ведёт на серверный экран. Таймер демонстрационного движка больше не помечает серверный экран как устаревший.
- UUID `session_id` позволяет принять версию 0 после перезапуска backend. Старые ответы не откатывают новую сессию или историю; сообщения об ошибках действий не исчезают при успешном опросе.
- Снимок сеанса и его наблюдаемый dashboard теперь используют одну дату и версию даже на границе смены кадра воспроизведения. `/api/dashboard` наследует длительность периода текущего сеанса, если параметр не указан.
- Некорректные JSON-веса, порядок признаков и нечисловые параметры отключают модель без ложного частичного расчёта.
- GitHub Actions проверяет Python, тесты frontend, стандартную production-сборку и совместный smoke-тест. Скрипт `scripts/smoke_app.py` проверяет ресурсы собранного интерфейса, ML, изменение входов, остановку, историю и сброс.
- Уточнены инструкции: GitHub содержит исходники, а не готовый ZIP с `dist`, `wheelhouse` и Cloudflare. Linux-скрипт запуска сообщает о пропущенной сборке frontend.

CSS, шрифты, изображения, 3D-компоненты и расположение существующих панелей не изменялись. Дополнено содержимое уже существующей панели прогноза.

## Воспроизведение проверки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
cd frontend
npm ci
npm test
npm run build
cd ..
python scripts/smoke_app.py
```

Локально: **58 backend-тестов + 11 subtests**, **15 frontend-тестов**, TypeScript и совместный smoke-тест прошли. Новый вход через `/api/ingest` меняет числовой прогноз, который совпадает с прямым вызовом загруженной модели. Остановка окраски на 60 минут даёт 100,69 → 94,63 модельного годного выпуска, потерю около 6,06 автомобиля. Фактические показатели и прогноз по наблюдаемым данным при остановке не переписываются.

В локальном Windows sandbox стандартная сборка упиралась в `EPERM` у `realpath`. Сборка через тот же конфиг с локальным параметром `resolve.preserveSymlinks=true` прошла; этот параметр в репозиторий не добавлен. Стандартная команда отдельно проверяется в GitHub Actions. В текущем окружении браузер не смог подключиться к тестовому localhost-серверу; повторный интерактивный проход не заявляется. HTTP-маршруты, ресурсы, расчёты и контракт отображения проверены тестами. Предыдущие наблюдения браузера в VALIDATION.md относятся к более раннему запуску.

## Границы результата

Модель обучена на внешнем синтетическом MFG-005, не на истории отказов Allur. ROC-AUC тестовой выборки — 0,6164, доля ложных тревог — около 77,9%. Её баллы не откалиброваны для Allur. Цель — ≥60 минут незапланированного простоя в следующей имеющейся записи той же линии; длительность будущей остановки модель не предсказывает. Для промышленного применения нужны реальные данные и отдельная валидация. Состояние хранится в памяти одного процесса; после перезапуска сбрасывается.
