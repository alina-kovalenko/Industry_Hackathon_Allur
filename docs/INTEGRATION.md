# Передача ИИ и расчётов участнику команды

Готовый `/state` на сервере команды можно сохранить. `allur/integration.py` экспортирует `build_state` и `calculate_stop_scenario`; оба принимают исходный словарь case.json. Модуль не запускает сервер и не зависит от FastAPI или sklearn.

```python
from allur.engine import load_case
from allur.integration import build_state, calculate_stop_scenario

case = load_case()
state = build_state(case, date="2026-10-02", scheduled_hours=8)
# В существующем обработчике /state вернуть state как JSON.
result = calculate_stop_scenario(case, {
    "id": "painting", "equipment_id": "Камера-02",
    "date": "2026-10-02", "scheduled_hours": 8,
    "horizon_minutes": 480, "stop_minutes": 60,
})
```

## Поля состояния

Ответ — ровно `{"sections": [...]}`. Идентификаторы: `welding` = сварка, `painting` = окраска, `assembly` = сборка. Если интерфейс использует другие id, замените их в адаптере на границе API; единицы и формулы сохраняются.

`throughput` — валовой выпуск / длительность выбранного периода в часах, по умолчанию 8. Это выпуск с учётом потерь времени за период, а не скорость только во время работы. `defect_rate` — брак / валовой выпуск, доля; для процентов умножить на 100. `queue` — количество автомобилей; неизвестное значение `null`. Нельзя подставлять 0: это означало бы отсутствие очереди.

`downtime_minutes` — сумма записей журнала оборудования участка на выбранную дату. У записей нет времени начала/конца: значение не доказывает, что участок стоит сейчас, и не равно непересекающемуся простою линии. `status` — учебная классификация: `stopped` при нулевых выпуске и времени работы; `warning` при браке выше 2%, недовыполнении плана или записанном простое; иначе `running`. Это статус агрегированного среза, не SCADA-телеметрия.

В датасете нет отдельных показателей склада, контроля качества и готовой продукции. Если такие узлы есть в интерфейсе, их параметры нужно отмечать как неизвестные.

## Пример на 02.10.2026

| id | throughput, авто/ч | queue | downtime_minutes | defect_rate |
|---|---:|---|---:|---:|
| welding | 13.875 | null | 30 | 0.027027027 |
| painting | 14.5 | null | 0 | 0.051724138 |
| assembly | 14.875 | null | 55 | 0.016806723 |

Все три учебных статуса этой даты — `warning`; причины различаются. Полный JSON: `examples/state_2026-10-02.json`.

## Остановка участка

`stop_minutes` — **дополнительная** гипотетическая остановка внутри горизонта `horizon_minutes`. Записанный простой повторно не вычитается. Сценарий уменьшает валовую мощность выбранного участка на долю `stop_minutes / horizon_minutes`, последовательно ограничивает поток мощностью каждого этапа и применяет его долю годного выхода.

Пример: остановка окраски на 60 минут при горизонте 480 минут, исходный период 8 часов. Базовый расчёт — ≈100,69 годных автомобилей, сценарий — ≈94,63, потеря — ≈6,06. Дробные числа — ожидаемая мощность агрегированной модели. Наблюдаемый годный выпуск сборки в исходнике равен 117; отличие от базового расчёта связано с отсутствием начальных межоперационных запасов и последовательным учётом брака. Фактический KPI нельзя заменять результатом сценария.

Время начала остановки и движение отдельных автомобилей не моделируются. Предполагаются постоянные скорости и неизменное качество; буферы, повторная обработка, нехватка материалов и общие ресурсы не учтены. Это оценка мощности, не дискретно-событийная симуляция и не ML-прогноз.

Порог — 60 минут за календарные сутки **на единицу критического оборудования**. В примере у Камера-02 за 02.10 не зарегистрировано предыдущих событий: 0 + 60 = 60, `threshold.exceeded=false`. При 90 минутах расчёт выполняется с `true`. Критичность оборудования и полнота журнала неизвестны, поэтому проверка предварительная. Сценарий считается внутри одного выбранного дня; горизонт через полночь не реализован.

## Вызов отдельного backend

```javascript
const response = await fetch('http://127.0.0.1:8001/api/scenarios/stop', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    id: 'painting', equipment_id: 'Камера-02', date: '2026-10-02',
    scheduled_hours: 8, horizon_minutes: 480, stop_minutes: 60
  })
});
if (!response.ok) throw new Error(await response.text());
const result = await response.json();
```

Для браузера задайте разрешённый origin при запуске backend. PowerShell: `$env:ALLUR_ALLOWED_ORIGINS='http://localhost:3000'`. Альтернатива — импортировать функции в сервер или проксировать запросы с него. `localhost` на компьютере участника указывает на его компьютер; примеры не подключаются к удалённому серверу автоматически.

Ошибки ввода — HTTP 422. `/state` и расчёт сценария не меняют исходные данные. Полная схема: `docs/openapi.json`.

## Подключение модели

Шесть полей `/state` подходят для отображения состояния. Для ML дополнительно нужны исходные `planned_units`, `actual_units`, `runtime_hours`, `defects`, `date`, `line_id` и выбранные `scheduled_hours`. Их можно хранить внутри сервера, не расширяя ответ `/state`: план и фактическое время работы невозможно достоверно восстановить из шести отображаемых полей.

`POST /api/predict` принимает `{records: [...], scheduled_hours: 8, as_of: "2026-10-02"}`. Каждая запись имеет ту же схему, что `/api/ingest`, включая `utilization_pct` (для совместимости; в ML он не используется). Ответ `{prediction: {...}, model: {...}}` содержит оценки по линиям и метрики модели. Запрос не меняет состояние. `as_of` исключает будущие записи. Примеры: `examples/prediction_input.json` и `examples/prediction_result.json`.

Модель экспериментальная, её баллы не следует превращать в подтверждённые поломки или автоматически присваивать по ним `status=stopped`. Подробности — `docs/MODEL_CARD.md`.
