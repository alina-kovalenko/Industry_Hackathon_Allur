# Запуск прототипа Allur

## Готовый комплект для Windows

1. Распакуйте `Allur-prototype.zip` целиком в папку с правом записи.
2. Запустите `start-local.cmd` двойным щелчком. Первый запуск создаёт `.venv` и устанавливает зависимости из вложенного `wheelhouse`, без обращения к интернету.
3. Откройте **http://127.0.0.1:8001/app/**. Для остановки сервера нажмите Ctrl+C в его окне.

Нужен Python **3.12 x64**. Скрипт использует `ALLUR_PYTHON`, Windows launcher `py -3.12` или встроенный Python установленного Codex. Python, установленный в Codex на компьютере участника, подходит. На другом ноутбуке установите Python заранее; набор Windows wheels рассчитан на CPython 3.12 x64. Node.js для готового комплекта не нужен.

Если порт занят: `powershell -ExecutionPolicy Bypass -File .\start-local.ps1 -Port 8002`, затем откройте http://127.0.0.1:8002/app/.

Локальный интерфейс, шрифты, API, данные и JSON-модель не требуют внешних сервисов. Swagger по `/docs` использует CDN и без интернета может не отобразиться; `/openapi.json` и основной интерфейс работают локально.

## Разработка из репозитория

Python 3.12, Node.js ≥22.12. Выполните в корне:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime.lock
cd frontend
npm ci
npm run build
cd ..
.\start-local.cmd
```

Для frontend с обновлением исходников: отдельно запустите `npm run dev` в `frontend`, оставив backend на 8001. Откройте адрес Vite с `/app/`; Vite проксирует `/api` на backend. Указывать CORS для этого варианта не требуется. Для отдельного frontend на другом origin задайте `ALLUR_ALLOWED_ORIGINS` перед запуском backend, например `http://localhost:3000`.

## Демонстрация

1. Вкладка **«Данные сервера»** открывается по умолчанию. Три участка используют реальные тестовые срезы кейса.
2. Нажмите **«Воспроизвести данные»**. Даты 01.10 и 02.10 меняются с заданным интервалом; интерфейс опрашивает backend каждую секунду.
3. Выберите окраску и остановку 60 минут, нажмите **«Запустить сценарий»**. Воспроизведение приостанавливается; мощности окраски и сборки уменьшаются. На срезе 02.10 модельный годный выпуск: 100,69 → 94,63, потеря ≈6,06 автомобиля.
4. Проверьте объяснение, кандидата в узкое место, предварительную проверку порога и запись в истории.
5. **«Сбросить сценарий»** восстанавливает исходный срез 02.10, убирает сценарий и импортированные записи, останавливает воспроизведение. История сохраняется, чтобы показать действия.

Остальные вкладки сохранены из предоставленного frontend: отдельная иллюстративная симуляция 12 станций в браузере. Это не сведения о реальном оборудовании Allur и не расчёты backend. Отсутствующие очереди на вкладке сервера показаны как «Нет данных».

Фактические KPI отображаются отдельно от проекции сценария. Расчётный модуль оценивает относительное уменьшение потока без буферов; абсолютный модельный выпуск отличается от зарегистрированных 117 годных автомобилей. Каждый сценарий заменяет предыдущий на исходном срезе, а не накапливает остановки.

## Доступная ссылка

Готовый комплект содержит `tools/cloudflared.exe` из официального выпуска Cloudflare. Сначала запустите `start-local.cmd`, затем `share-demo.cmd`. Откройте напечатанную HTTPS-ссылку, добавив `/app/` в конец. Эта ссылка временная: адрес меняется при новом запуске и перестаёт работать после остановки туннеля/сервера либо выключения ноутбука. Обе консоли должны оставаться открытыми.

Для постоянного размещения на выбранном хостинге используйте Dockerfile: он собирает frontend и запускает Python API одним процессом. HTTP-порт берётся из `PORT`, адрес — из `HOST`; в контейнере `HOST=0.0.0.0`. Проверка доступности: `/api/health`, интерфейс: `/app/`. Локальная проверка контейнера: `docker compose up --build`, тот же адрес 8001.

Состояние общее для всех посетителей одного экземпляра и хранится в памяти. Перезапуск сервера сбрасывает сценарий, импорт и историю. История ограничена последними 500 событиями. Для демонстрации запускайте **один worker / один экземпляр**, иначе посетители могут получать разные сеансы.

## Проверка соединения

`GET /api/health` → status=ok; `GET /state` → три участка. `POST /scenario` с JSON ниже → результат расчётов. Повторный `GET /state` → изменённые показатели. `GET /history` → сохранённый сценарий. `POST /reset` → исходные показатели.

```json
{"id":"painting","equipment_id":"Камера-02","date":"2026-10-02","stop_minutes":60,"horizon_minutes":480}
```

Исходный `POST /api/scenarios/stop` оставлен как предварительный расчёт без изменения состояния, для совместимости с модулем первого участника.
