# Карточка модели: экспериментальный риск простоя

## Назначение и границы

Модель демонстрирует воспроизводимый прогноз следующей записи для прототипа. Она не прошла валидацию на производственных данных Allur и не предназначена для планирования смен, техобслуживания или решений по безопасности. `score_pct` — сырой score логистической модели, а не калиброванная вероятность отказа. Модель не предсказывает длительность простоя; `predicted_downtime_minutes` остаётся `null`.

## Данные и постановка

Обучающий источник — синтетический [MFG-005 sample](https://huggingface.co/datasets/xpertsystems/mfg005-sample/tree/427854b6ec8cddc3f929685d9efd58bfdc2a8af3), 3 000 сменных записей 36 линий. Для каждой линии записи упорядочены по дате и смене. Признаки берутся из текущей записи *t*: доступность, выполнение плана и выход годной продукции. Цель — наличие не менее 60 минут незапланированного простоя в следующей доступной записи *той же линии*. Таким образом, признаки текущей записи не включают целевое событие следующей записи.

Разбиение только по уникальным датам целевой записи и в хронологическом порядке: обучение до 2023-07-03, подбор порога на валидации до 2024-04-02, финальный тест с 2024-04-03. В разбиениях 2 016 / 482 / 466 пар; тест содержит 45,7% положительных наблюдений. Применяется стандартизированная логистическая регрессия с весами классов; порог F1 выбирается только на валидации.

## Результат финального теста

| Метрика | Модель | Постоянный prevalence baseline |
|---|---:|---:|
| ROC-AUC | 0,616 | 0,500 |
| Average precision | 0,547 | 0,457 |
| Brier score | 0,242 | 0,248 |
| Accuracy при выбранном пороге | 0,545 | 0,543 |
| Precision / recall / F1 | 0,501 / 0,930 / 0,651 | 0 / 0 / 0 |
| False positive rate | 0,779 | 0 |

Для полноты приведён также always-positive baseline: accuracy 0,457, precision 0,457, recall 1,0, F1 0,627 и false-positive rate 1,0. Модель увеличила F1 до 0,651, но пометила как положительные 395 из 466 тестовых записей и ошиблась в 197 из 253 отрицательных случаев. Это слабый ранжирующий сигнал с высокой частотой ложных тревог; accuracy почти совпадает с prevalence baseline. Полные воспроизводимые показатели сохранены в `models/training_report.json`.

## Применение к Allur

Адаптер оценивает последнюю запись каждой линии отдельно: `runtime_hours / scheduled_hours` (не выше 100%) как proxy доступности, `actual_units / planned_units` как выполнение плана, а выпуск за вычетом `defects` — как выход годной продукции. Это соответствие признаков условное: синтетический источник имеет сменное OEE, Allur передаёт дневные строки. Интервал до следующей записи MFG-005 в тестовой части: медиана 14 дней, максимум 129 дней; календарный срок прогноза переменный. Переносимость на Allur не проверена. UI/API обязаны называть score экспериментальным и показывать эти ограничения.

## Ограничения

- Источник MFG-005 синтетический, англоязычный и не представляет завод Allur.
- Только три широких производственных признака; отсутствуют реальные события и телеметрия Allur.
- Внешние наборы Zenodo описаны отдельно, но не смешивались с обучающей выборкой из-за другого домена и временного шага.
- Доля простоя ≥60 минут зависит от источника; этот порог — демонстрационное определение события.
- Для пригодного применения нужны согласованные исторические сменные данные Allur, временное тестирование, проверка калибровки и согласованный рабочий горизонт.
